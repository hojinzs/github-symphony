Method: unified diff of the two spec versions, then six parallel code audits (config, domain/tracker, orchestrator, workspace, runtime/secrets, prompt/observability/HTTP/CLI), each classifying every concrete requirement with `path:line` evidence. Classification used throughout:

| Class                     | Meaning                                                                       |
| ------------------------- | ----------------------------------------------------------------------------- |
| **A — Drift**             | Implementation matched the old spec; the new spec changed the rule            |
| **B — Never implemented** | Required by the old spec too (unchanged or only reworded), missing or wrong   |
| **C — Divergent**         | Intentional repository choice; noted whether it is documented as a divergence |
| **E — Other**             | Bugs, dead code, doc errors, test gaps noticed while auditing                 |

Priority: **P1** = operator-visible incorrectness or security; **P2** = spec MUST/REQUIRED conformance; **P3** = SHOULD/docs/tests.

## 1. What changed upstream

The upstream spec moved from a Linear-specific document to a tracker-agnostic contract. Grouped by impact on this repository:

| Area                           | Old (local copy)                                                                                                   | New (upstream)                                                                                                                                                                                                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Normative language             | prose "should/may"                                                                                                 | RFC 2119 `MUST`/`SHOULD`/`MAY`; "implementation-defined" behaviour MUST be documented                                                                                                                                                                                                                 |
| `tracker` config (§5.3.1)      | flat `endpoint`/`api_key`/`project_slug`, comma-string states allowed, core defaults `Todo, In Progress` / `Done…` | `tracker.kind` + opaque `tracker.provider` object (adapter-owned, unknown keys preserved), `tracker.required_labels` (ALL-of, case-insensitive), `active_states`/`terminal_states` REQUIRED unless the adapter profile documents a default, lists only                                                |
| Issue model (§4.1.1, §11.3)    | `id`, `identifier`, …, `blocked_by`                                                                                | adds `native_ref` (opaque, non-secret), `assignee_id`, **`dispatchable` (REQUIRED explicit boolean, adapter-derived)**; `identifier` MUST be unique in scope; labels trimmed/lowercased/deduped/blank-dropped; timestamps parsed RFC 3339                                                             |
| Eligibility (§8.2)             | orchestrator applies "Todo + non-terminal blockers → skip"                                                         | orchestrator applies only `dispatchable === true` + `required_labels`; `issue_routable()` used for refresh/continuation; orchestrator MUST NOT branch on provider blocker/board/comment semantics                                                                                                     |
| Sorting (§8.2)                 | priority ascending, null last                                                                                      | priority `1..4` bucket first; all other integers sort with null; `created_at` null last                                                                                                                                                                                                               |
| Adapter ops (§11.1)            | `fetch_candidate_issues`, `fetch_issues_by_states`, `fetch_issue_states_by_ids` (minimal)                          | `fetch_issues_by_states(state_names)` + `fetch_issues_by_ids(issue_ids)` returning **full snapshots**; empty input → empty output without a provider call; state-list MAY omit malformed records (log), ID-refresh MUST fail on malformed; candidate polling MUST include `dispatchable=false` issues |
| Retry handling (§8.4, §16.6)   | refetch all candidates, find by id                                                                                 | `fetch_issues_by_ids([id])`; terminal → clean workspace + release; fetch failure → requeue `retry refresh failed`; no slots → requeue `no available orchestrator slots`                                                                                                                               |

| `workspace.root`               | bare relative names preserved                                                                                      | `~` expanded, relative resolved against the `WORKFLOW.md` directory, normalized absolute                                                                                                                                                                                                              |
| Validation (§5.3)              | string integers coerced; bad `hooks.timeout_ms` falls back                                                         | integer-only; invalid `hooks.timeout_ms` and non-positive `agent.max_turns` (default 20, now a core field) **fail validation**                                                                                                                                                                        |
| Agent runner (§10)             | inline JSON-RPC transcript, line framing rules                                                                     | defers to the targeted Codex app-server protocol; `turn_timeout_ms` is a **silence** interval reset on every output, not a total cap                                                                                                                                                                  |
| Agent tools (§10.5, §15.3)     | optional `linear_graphql` tool                                                                                     | adapter hooks `agent_tool_specs()`, `secret_environment_names()`, `execute_agent_tool(name, args, context={issue})`; tools execute **host-side**; tracker secrets MUST NOT be inherited by the child; tool specs bound to one session snapshot; per-adapter tool docs required                        |
| Adapter profile (§11.2)        | —                                                                                                                  | each adapter MUST publish a compact profile (kind, provider keys, secrets, scope/pagination, `id`/`native_ref` mapping, normalization, tools, error-category mapping)                                                                                                                                 |
| Error categories (§11.4)       | `linear_api_request`, `linear_api_status`, …                                                                       | `invalid_tracker_config`, `missing_tracker_secret`, `tracker_request`, `tracker_status`, `tracker_response`, `tracker_pagination`, `tracker_rate_limited`                                                                                                                                             |
| Snapshot (§13.3)               | `running`/`retrying` rows                                                                                          | rows SHOULD include tracker `issue_url`                                                                                                                                                                                                                                                               |
| `attempt` (§12.3)              | first/continuation/retry                                                                                           | 1-based integer on any later run, null on first; optional `retry_kind`                                                                                                                                                                                                                                |
| HTTP extension (§13.7)         | `server.port` mentioned in §5.3                                                                                    | `server` key formally owned by the extension; `--port` overrides                                                                                                                                                                                                                                      |
| Restart recovery (§2.1, §14.3) | "no persistent DB"                                                                                                 | clarified: exact in-memory scheduler state (timers, sessions) is not restored                                                                                                                                                                                                                         |
| Appendix A                     | —                                                                                                                  | OPTIONAL SSH worker extension (`worker.ssh_hosts`, per-host caps, remote `workspace.root`)                                                                                                                                                                                                            |

## 5. Recommended sequencing

The findings cluster into five workstreams. Ordering favours operator-visible correctness first, then the tracker-agnostic model (which unlocks most of the remaining drift), then documentation.

1. **Correctness hotfixes (no model change)** — A7 (retry refresh + blind restart), A8 (GitHub terminal cleanup), B1 (`attempt`), B2/B3 (fatal hooks, hooks on retry), B11 (tick isolation), B12 (subprocess exit), B9 (per-state key normalization), B14 (Linear labels), A12 (silence timeout). Each is a contained change with a clear test.
2. **Tracker-agnostic issue model** — A1 + A9 + A10 + A18 (`dispatchable`, `assigneeId`, full ID-refresh snapshots, adapters return unassigned issues), then A2 (blocker rule into adapters), A3 (`required_labels`), A14 (`nativeRef`, remove provider branching from `service.ts`). Ship behind the existing contract with compatibility shims; `repo explain` must show the new reasons.
3. **Config layer** — A4/A5/A6 (`tracker.provider`, adapter defaults, strict validation), B5/B6 (`~`, `$VAR` scope), B7/B8 (optional front matter, startup preflight, supported-kind check before reconciliation), B17 (typed errors), B24 (`server` key). Keep flat keys as deprecated aliases with `doctor` diagnostics.
4. **Secrets and tools** — A13 decision (host-side execution via broker vs documented MCP-subprocess model), `secretEnvironmentNames()` on the adapter contract, strip from Codex/Claude child env, pass issue context to tools, delete or fix E2. B13 (approval policy) belongs here.
5. **Documentation and spec sync** — sync `docs/symphony-spec.md` to upstream `8001b52` in a dedicated PR (AGENTS.md forbids editing it during normal work, so make the sync its own reviewed change and update `docs/README.md`'s "Draft v1" label); write adapter profiles (A16); label the C1–C13 divergences; fix D1–D8; retire `2026-06-25-spec-gap-analysis.md` pointers to this report. Workspace key hashing (A11) needs a migration note and can ride with either stream 2 or 5.

Items explicitly **not** recommended: implementing Appendix A (SSH workers) — OPTIONAL and orthogonal to the repo's single-repo/standalone model; note it as out of scope in `docs/architecture.md`.
